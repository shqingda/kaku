# 架构 Review 修复计划（2026-10-16）

来源：[项目代码架构 Review](chatgpt-conversation://6ad1bee1-7bd4-83ec-bba3-93287d29aa9f)，基于旧提交 b7b50a9；逐项以当前源码和仓库测试重新确认。

## 约束和设计

- 保留 mobile / api / web / shared 分层，不引入通用 Provider 框架。
- 每个行为先用受控时序测试复现，再最小修复。原覆盖率、兼容性和 CI 门禁保持不变。
- 本机账号、钥匙串、草稿和历史保持原样，不通过退出或清理准备测试；不恢复已撤回的章节呈现改动。
- 新登录要求本机 verifier / S256 challenge / requestId；已有 session 及 token refresh 协议保留。
- D1 保存连接 generation，刷新只条件更新既有 generation；跨 Worker 刷新由数据库原子占用协调。
- 推送订阅绑定 session 与 registrationId，撤销通过数据库级联生效；legacy 无归属登记保留但暂停投递，正常重新登记后恢复。
- 单集进度按 episode ID 增量提交；明确批量覆盖检查基线。上游没有 CAS，因此不能承诺覆盖上游网页的任意并发写入。
- API/mobile 共享真正跨边界的认证与收藏契约；配置显式区分 API 地址，开发中不隐式切换现有账号的服务端。
- 迁移、部署和原生安装包是独立发布步骤；本轮先交付测试通过、可审查的代码与迁移，不直接修改生产数据。

## 顺序与验收

- [x] 1. 登录绑定：缺失/错误 verifier 无法兑换；错误兑换不消费合法 handoff；handoff 绑定原连接 generation，消费后撤销也不能重新签发会话；无本机 pending 的回调拒绝；合法重复回调只完成一次。
- [x] 2. 凭据生命周期：暂停刷新后断开/重新连接，迟到刷新不能重建/覆盖新 generation；并发仅一个上游刷新，等待者有界重读，忙碌不强制退出。
- [x] 3. 设备推送撤销：D1 实测撤销 B 后不再安排 B 投递，A 和其他账号不受影响；读取通知期间撤销也重新校验；过期/legacy 订阅不发。
- [x] 4. 账号作用域：A 的 queued mutation 在 B 登录后拒绝，旧响应不回填缓存；同账号重新登录使旧命令失效，普通 token refresh 不影响合法命令。
- [x] 5. 章节正确性：不同 ID 的增量互不撤销，0.5/1/1.5 不混淆；批量缺基线/冲突在任何写入前拒绝；部分成功/结果不明保留编辑并要求确认。
- [x] 6. 网络截止时间：传入 Query signal 仍有 12 秒超时；主动取消与超时区分，计时器/监听器释放。
- [x] 7. 可靠限流：登录、交接和写入按独立预算使用 D1 原子计数；100 并发不能突破 40 阈值，跨窗口恢复；公开浏览保留低成本削峰。
- [x] 8. 推送回执：ticket 持久化并与游标原子提交，receipt 永久错误清理匹配版本的登记，晚到回执不删除新登记；显式超时、分片及有限并发，慢用户不阻塞其他用户。
- [x] 9. 集成检查：共享契约、显式 API 配置、迁移保留已有数据；全工作区类型检查、逻辑/UI/覆盖率、Expo 检查与双平台打包；完整 diff 和安全边界审查后分批提交。
