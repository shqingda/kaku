# 2026-10-03 启动、缓存与包体优化

本轮从 `49b7cb8` 开始，按小切片提交，目标版本为 v1.1.16。当前实现与规则见 [架构](../architecture.md)，剩余设备验收见 [TODO](../../TODO.md)。

## 改动与验证重点

- 首页不再启动预挂载频道、排行、社区、综合四页，保留用户按下入口时的数据预取；五个收藏查询订阅合并为当前分类一个，下拉仅刷新当前分类与动态。
- 收藏预取和页面共用 query options，预取失败正常结束并保留查询错误状态；动态后台刷新失败保留缓存并提供重试，恢复成功后提示消失。
- 动效偏好共用一个原生订阅和初始读取，最后消费者卸载后清理；初始值保守减少动态效果，处理读取拒绝、迟到结果与重新挂载竞态。不会将模拟动画测试当成真实手感验收。
- 查询磁盘快照最多 100 个近期结果、每个无限列表前两页、总 JSON 2 MiB；保存和恢复两端执行。每条结果按自身更新时间淘汰超过 24 小时的数据，保留私有标记、版本和分页游标。当前内存列表与独立离线作品包保持完整。
- 临时搜索在无订阅后保留 10 分钟；更新 Provider 每次挂载只读取一次本机提醒记录，后续状态变化沿用内存值。
- 使用 Sentry 7.11.0 支持的 `includeWebReplay: false`，裁剪未使用的网页回放依赖，保留崩溃与 tracing。没有套用新版 SDK 才支持的 feedback 开关，也没有升级依赖。依据：[官方 Metro 配置](https://docs.sentry.io/platforms/react-native/manual-setup/metro/)。

## 可重复的量化边界

Android production export 使用相同 Node、依赖和 Metro 参数：`pnpm --filter @kaku/mobile exec expo export --platform android --source-maps --output-dir <输出目录>`。

| 中间产物 | 优化前 | 裁剪后 |
| --- | ---: | ---: |
| Hermes 字节码 | 6,374,248 B | 6,178,816 B |
| source map 中 Web Replay / Replay Canvas | 2 个模块 | 0 |
| Sentry core / React Native 模块 | 176 / 107 | 176 / 107 |

字节码减少 195,432 B（3.07%）。此时已包含动效订阅改动，不把整个差额严格归因于单个开关；最终安装包另行核验。原有 R8 与资源裁剪已在 v1.1.15 开启，不重复记作本轮收益。

合成快照使用 200 个查询、每个 10 页、每页 20 项；每项包含编号、中文标题及重复 20 次的“中文测试内容”。结果从 16,602,279 B / 200 条降至 1,673,179 B / 100 条，减少 89.92%，原对象仍保留完整页数。Node 下三次 JSON.parse 中位数为 10.384 ms → 1.128 ms；这仅是合成数据的桌面解析测量，未包含实际存储读取、水合和渲染，不是手机冷启动或 RSS/堆内存指标。旧版大快照首次升级仍需读取、解析旧文件，再缩减；后续写入才受新大小限制。
