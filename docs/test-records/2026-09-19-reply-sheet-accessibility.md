# 2026-09-19 回复弹层无障碍树修复

## 问题与修改

iPhone 18 Pro / iOS 27.0 开发客户端上，首次打开章节回复框时能访问输入框；关闭后再打开，截图仍显示弹层，Maestro 的原生无障碍树却只剩应用根节点、开发工具和系统状态栏。

`AppSheet` 在原生 `Modal` 内，给 `KeyboardAvoidingView` 和动画面板都设置了 `accessibilityViewIsModal`。对照实验结果：

- 原实现复现失败；恢复原实现后再次复现。
- 只删除动画面板的标记曾单次通过，但连续重开仍失败，不作为修复。
- 删除两个子容器的标记后，交由原生 `Modal` 管理模态展示；重复开关时输入框、发送按钮可访问，背景章节仍不可访问。

本次仅修改子容器的无障碍标记，同时把弹层的现有间距等值换成 `SPACING` token。草稿存储、编辑器重建、动画及关闭回调均保留。未修改 React Native 原生源码。

## 验证方式

新增独立流程 `.maestro/reply-sheet-accessibility-ios.yaml`，前置为已登录的 iOS 开发客户端和运行中的 Metro。每轮冷启动，通过已有搜索深链进入章节，先证明背景章节可见，再打开回复框并连续关闭/重开三次：

- 输入框在关闭后消失、重开后重新可访问。
- 发送按钮可访问。
- 弹层打开期间，背景“第 1 集”不可访问。
- 最后关闭弹层，章节讨论入口恢复。

流程不输入、不清空也不发送内容，保留已有草稿。截图核对弹层内容及布局。由于当前没有 Argent 工具，使用 Maestro 原生树及 simctl/流程截图；这不等于实际 VoiceOver 朗读验收。
