# Expo SDK 58 升级验证

## 范围与版本

从 Expo 57.0.30 升级至正式版 58.0.19。以该 npm 发布包的
`bundledNativeModules.json` 和 `expo install --check` 为兼容依据，
不把所有依赖直接升到 npm latest。

| 依赖 | 升级后版本 |
| --- | --- |
| React / React DOM | 19.3.0 |
| React Native / RN Metro config | 0.88.0 |
| Expo Router | 58.0.26 |
| Reanimated / Worklets | 4.7.1 / 0.13.0 |
| Gesture Handler | 3.3.0 |
| Screens / Safe Area Context | 4.30.0 / 5.10.1 |
| WebView | 14.0.1 |
| Sentry React Native | 8.28.0 |
| Jest / jest-expo / test-renderer | 30.5.2 / 58.0.12 / 1.3.0 |

其余已安装的官方 Expo 模块同步对齐 SDK 58。FlashList 2.3.3 与
TypeScript 7.0.2 保留项目既有的 Expo 检查排除配置；没有新增排除项。
官网与移动端的 React 类型统一为 19.3.0，避免 pnpm 因类型 peer 不同
生成两套同版本原生模块。官网运行时、API 和业务库的直接版本不变。

## 迁移处理

- RN 0.88 的组件实例 ref 改为 `ComponentRef<typeof TextInput/View/ScrollView>`，
  继续保留 focus、测量和滚动操作的类型检查。
- 列表没有头尾或空组件时传 `undefined`，适配新的 RN 属性类型。
- Router 集成测试等待 `renderRouter()` 返回结果；五个深链、返回、登录回跳
  和无效路由用例保留原断言。升级后曾出现的五项失败全部修复。
- 按仓库约定，将本次触及页面的裸字号和间距迁移到 `TYPE` / `SPACING`；
  原有非阶梯值就近归入现有阶梯，页面排版会有小幅变化。
- 移除 `ios.enableSceneSupport`：SDK 58 默认生成 UIScene 生命周期。
- 已检查通知显式 handler、图片下载、导航事件监听及 Sentry 初始化；
  未使用改变同步语义的 `File.write()` 或已移除的 SQLite libSQL API。

官方依据：[Expo 升级流程](https://docs.expo.dev/workflow/upgrading-expo-sdk-walkthrough/)、
[SDK 58 发布说明](https://expo.dev/changelog/sdk-58)、
[Router 57 → 58](https://docs.expo.dev/router/migrate/sdk-57-to-58/)、
[Sentry 7 → 8](https://docs.sentry.io/platforms/react-native/migration/v7-to-v8/)。

## 已知限制

- Android 已验证 JavaScript 导出，未执行 Android 原生构建或设备测试。
- 未执行需要新游客设备、退出登录或清空数据的流程。

- 额外运行移动端 `expo export --platform all` 时，Web 分支无法解析
  expo-sqlite 的 `wa-sqlite.wasm`。随后按 CI 的 iOS / Android 独立导出均成功。
  移动端 Web 未完成验证；独立官网构建通过。
- Sentry 8.28 的可选 Expo Router 集成探测旧的 `global-state/router-store`
  路径，Metro 会输出解析警告；移动端打包成功。真实 Sentry 上报未验收。
- `expo-quick-actions@6.0.2` 的旧构建工具间接依赖 `@expo/require-utils@55.0.8`，
  仍声明 TypeScript 5 的 peer 范围；未隐藏该警告或降级项目 TypeScript。
- 审计仍有 1 critical、34 high、10 moderate、2 low（升级前为
  1 critical、35 high、12 moderate、2 low）。包括开发工具链的
  `shell-quote@1.10.0`；不能把本次 SDK 升级视为安全审计全部通过。
  后续需按可达性单独处理，未使用强制修复或跨主版本 override。
